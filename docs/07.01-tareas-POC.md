# Tareas detalladas del POC

Este documento desglosa el alcance de [07-backlog-POC.md](07-backlog-POC.md) en entregas pequeñas. La aplicación del POC se implementa en `reformk/` con Razor Pages, ASP.NET Core Identity, EF Core y SQLite; los vídeos provienen de `youtube-analyzer/output`.

## Reglas de ejecución

- Ejecutar las tareas en orden y no comenzar la siguiente hasta cumplir el resultado observable de la actual.
- Mantener cada cambio dentro del flujo funcional descrito. No crear una SPA, un backend separado ni generar contenido con IA.
- Al terminar **cada tarea**, compilar desde la raíz del repositorio:

  ```powershell
  dotnet build .\reformk\Reformk.csproj
  ```

  La tarea queda bloqueada si la compilación falla; corregir el error de esa tarea antes de continuar.
- No se requieren tests automatizados. Usar las comprobaciones manuales especificadas y dejar la aplicación ejecutable.
- No borrar ni reutilizar `reformk/app.db` para validar una instalación limpia. Si hace falta, usar una base SQLite temporal y conservar intactos los datos locales.
- No guardar credenciales OAuth ni otros secretos en el código o en el repositorio. Google OAuth es opcional y solo se verifica si sus credenciales de desarrollo ya están configuradas.

## Secuencia de tareas

### 1. Confirmar el arranque y la base de datos

**Cambio mínimo**

1. Restaurar y compilar `reformk/Reformk.csproj`.
2. Revisar las migraciones existentes y la cadena `DefaultConnection`.
3. Aplicar las migraciones a una base SQLite temporal vacía con las herramientas de EF Core; no depender de la base personal existente.
4. Iniciar la aplicación en desarrollo y abrir la página inicial.
5. Si la aplicación no prepara el esquema desde cero, corregir únicamente el paso de inicialización necesario para el entorno local, sin cambiar el esquema de Identity.

**Resultado y medida**

- La aplicación inicia y responde en una URL local.
- La base temporal se crea con las tablas de Identity y el historial de migraciones, sin errores.
- Se conserva sin cambios el archivo `reformk/app.db` existente.

### 2. Verificar el acceso de usuario

**Cambio mínimo**

1. Reutilizar las páginas existentes de ASP.NET Core Identity.
2. Resolver en desarrollo la confirmación de cuenta que actualmente está requerida y puede bloquear el registro sin proveedor de correo. La excepción debe quedar limitada a desarrollo; mantener la política de producción.
3. Confirmar que registro, inicio y cierre de sesión funcionan con email y contraseña.
4. Comprobar Google OAuth solo si los secretos están ya disponibles fuera del código; si no, anotar que queda fuera de la verificación local.

**Resultado y medida**

- Una cuenta de prueba puede completar registro, inicio y cierre de sesión.
- Hay una sesión autenticada activa tras iniciar sesión y ninguna tras cerrarla.
- Las opciones de producción no quedan debilitadas.

### 3. Sustituir la portada de plantilla por navegación del POC

**Cambio mínimo**

1. Reemplazar el contenido de bienvenida de `reformk/Pages/Index.cshtml` por una portada breve de Reformk.
2. Añadir enlaces a “Crear proyecto” y “Mis proyectos”; pueden apuntar inicialmente a páginas pendientes, pero no deben aparentar que ya funcionan.
3. Mostrar la navegación de proyecto solo a usuarios autenticados y conservar los enlaces de acceso/cierre de sesión de Identity.

**Resultado y medida**

- La portada ya no muestra el contenido “Welcome / Learn about”.
- Un usuario autenticado ve dos destinos del POC y un usuario anónimo puede llegar al acceso.

### 4. Inventariar el corpus local

**Cambio mínimo**

1. Añadir un lector acotado al corpus `youtube-analyzer/output`, recorriendo sus carpetas por `videoId`.
2. Preferir `transcript.json` y utilizar `transcript.txt` solo como alternativa cuando corresponda.
3. Excluir archivos ausentes, vacíos o inválidos; capturar el motivo de exclusión y continuar con las demás carpetas.
4. Exponer un resumen visible solo a usuarios autorizados (o en el log de desarrollo si una pantalla añade alcance innecesario): total de carpetas, transcripciones utilizables y elementos omitidos agrupados por motivo.
5. Elegir entre 3 y 5 categorías iniciales a partir de los temas que realmente aparezcan en las transcripciones; guardar su asociación en una configuración sencilla y explícita.

**Resultado y medida**

- El resumen informa los tres conteos y la suma de omitidos por motivo coincide con el total omitido.
- Al menos una transcripción válida se lee y un archivo inválido no interrumpe el inventario.
- Las categorías iniciales corresponden a contenido encontrado, no a métricas de `analysis.json`.

### 5. Persistir el catálogo de vídeos de forma repetible

**Cambio mínimo**

1. Añadir la entidad mínima de catálogo: `videoId`, texto utilizable de transcripción y categoría/palabras clave asignadas.
2. Añadir la configuración correspondiente al contexto EF Core y crear una migración nueva, conservando las tablas de Identity.
3. Implementar una importación que inserte o actualice por `videoId`; una segunda ejecución no debe duplicar filas.
4. Importar solo elementos válidos del inventario y registrar cuántos se insertaron, actualizaron y omitieron.

**Resultado y medida**

- La base contiene una fila por cada `videoId` importado y el recuento coincide con el resumen del inventario.
- Ejecutar la importación dos veces deja el mismo número de vídeos; la segunda ejecución crea cero duplicados.
- La aplicación arranca con la migración aplicada.

### 6. Guardar un proyecto y recomendar vídeos

**Cambio mínimo**

1. Añadir la entidad de proyecto con identificador, propietario Identity, descripción, categoría opcional y fecha de creación.
2. Añadir la relación entre proyecto y vídeos recomendados, incluyendo el orden o puntuación suficiente para reproducir el resultado.
3. Crear una migración y un formulario Razor Pages protegido para describir el proyecto y elegir una categoría opcional.
4. Validar que la descripción no esté vacía; persistir el proyecto antes de mostrar el resultado.
5. Crear un servicio sencillo y explicable de relevancia por coincidencia de términos normalizados entre descripción/categoría y transcripción. Limitar a tres resultados y ordenar por puntuación; no llamar a IA ni buscar fuera del catálogo.
6. Guardar los `videoId` seleccionados con el proyecto. Si no hay coincidencias, mostrar un estado vacío y permitir volver a editar.

**Resultado y medida**

- Una descripción válida crea exactamente un proyecto en SQLite y una vacía no lo crea.
- Para una búsqueda que coincida con el corpus se muestran de 1 a 3 vídeos importados, ordenados por puntuación.
- Para una búsqueda sin coincidencias se muestran cero vídeos y un mensaje explícito.
- Al reiniciar la aplicación se conservan el proyecto y sus identificadores recomendados.

### 7. Consultar proyectos propios

**Cambio mínimo**

1. Añadir “Mis proyectos” con los proyectos del usuario autenticado, ordenados del más reciente al más antiguo.
2. Añadir una página de detalle que cargue los vídeos guardados con el proyecto, sin recalcular recomendaciones al abrir el historial.
3. Aplicar el filtro por el identificador del usuario en las consultas de lista y detalle, no solo ocultar enlaces en la interfaz.
4. Mostrar estado vacío cuando no haya proyectos.

**Resultado y medida**

- Un proyecto creado aparece una vez en el historial y abre el mismo conjunto de resultados después de reiniciar.
- Una cuenta sin proyectos ve un estado vacío.
- Al intentar abrir desde otra cuenta el identificador de un proyecto ajeno, la aplicación devuelve no encontrado o acceso denegado y no revela sus datos.

### 8. Presentar vídeos y contabilizar aperturas

**Cambio mínimo**

1. Mostrar para cada recomendación el `videoId`, la miniatura `https://img.youtube.com/vi/{videoId}/hqdefault.jpg` y el enlace `https://www.youtube.com/watch?v={videoId}`.
2. No inventar título ni canal. Añadirlos únicamente si una integración ya configurada los proporciona.
3. Enrutar la apertura a través de una acción que valide que el vídeo pertenece al proyecto del usuario, incremente el contador de aperturas y redirija al enlace de YouTube.
4. Mostrar el total de proyectos creados (consultable desde SQLite) y el total de aperturas en una vista/resumen interno sencillo. No almacenar datos personales adicionales para esas métricas.

**Resultado y medida**

- Cada enlace abre el vídeo cuyo identificador aparece en la recomendación.
- Una apertura válida incrementa el contador exactamente en uno; una petición no autorizada no lo incrementa.
- El resumen permite observar el número de proyectos y aperturas sin consultar logs manualmente.

### 9. Recorrer la demostración completa

**Comprobación manual**

1. Arrancar con la base SQLite del POC y registrar/iniciar sesión con una cuenta de prueba.
2. Crear un proyecto con coincidencias y otro sin coincidencias.
3. Abrir “Mis proyectos” y verificar que ambos se conservan y muestran el resultado esperado.
4. Abrir un vídeo y verificar el destino y el incremento de una apertura.
5. Probar el detalle de un proyecto con una segunda cuenta y confirmar que no expone datos.
6. Ejecutar de nuevo el inventario/importación y comprobar que los totales no producen vídeos duplicados.
7. Revisar los conteos de proyectos y aperturas; anotar los valores observados y cualquier incidencia del flujo.

**Cierre y medida**

- Los seis comportamientos funcionales anteriores tienen un resultado observable, incluidos los estados vacíos y de acceso denegado.
- La importación repetida conserva el número de vídeos.
- Compilar una última vez con `dotnet build .\reformk\Reformk.csproj` y dejar la aplicación arrancable con `dotnet run --project .\reformk\Reformk.csproj`.

## Fuera de estas tareas

No implementar SvelteKit, planes de reforma generados por IA, descarga automática de vídeos, clasificación completa del corpus, marketplace, pagos ni preparación para producción. Mantener el alcance y los criterios del POC original.
